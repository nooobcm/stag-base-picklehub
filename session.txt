Implement an improved admin navigation and authentication protection system for STAG-BASE.

Problem:

When an administrator accidentally presses the browser Back button, they may be redirected to the login screen even though they have not intentionally logged out.

I want to prevent this behavior while maintaining proper authentication security.

Required behavior:
1. If an authenticated admin presses Back or Forward, allow normal browser navigation between authorized pages.
2. If an authenticated admin reaches the login page through browser navigation, redirect them to the admin dashboard.
3. Refreshing an admin page must not unnecessarily log them out.
4. Restoring a browser session must work when the admin closes and reopens the browser, provided the Supabase session remains valid.
5. If the session genuinely expires or becomes invalid, redirect to login appropriately.
6. Temporary network failures must not automatically destroy the admin session.
7. Actual logout must still invalidate the session and prevent access to protected admin pages.
Technical investigation:

Inspect the existing implementation before making changes.

Pay particular attention to:
- React Router navigation and route guards.
- Supabase auth initialization.
- getSession() and onAuthStateChange().
- Admin role verification.
- Login page redirection.
- Browser history and navigation behavior.
- Session persistence and token refresh.
Implementation requirements:
- Use a centralized authentication initialization process.
- Prevent route redirects before authentication initialization completes.
- Protect all admin routes.
- Redirect already-authenticated admins away from the login page.
- Preserve existing admin permissions and Supabase RLS policies.
- Do not disable the browser Back button.
- Do not use artificial history manipulation to trap users on the dashboard.
- Do not automatically log out users because of temporary network failures.
- Do not weaken authentication checks.
